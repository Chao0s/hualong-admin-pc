# ADR —— 管理端的架构决策记录

本目录记录**只属于管理端控制台**的架构决策：模块边界、视图划分、导航结构、本仓库自己的约定。

## 与其他记录的分工

| 放哪 | 记什么 |
|---|---|
| **本目录** | 管理端自己的架构决策。会重复出现、且下次遇到时希望一页就能裁决的那类 |
| [`../../decision.md`](../../decision.md) | 前端修改记录 —— 每次评审改了什么、涉及哪些页面、对 backend 有什么影响。按日期流水记 |
| `hualong-backend/DECISIONS.md` | 跨端的数据模型决议与代价。管理端的改动回冲后登记在那里（本仓库相关的是 **E9**） |
| `hualong-backend/docs/ADR-*` | 跨越三端的决策。**不要在本目录复制它们**，链接过去即可 |

判断标准：**这个决策只影响管理端吗？** 是 → 本目录；牵涉教师端/家长端/数据模型 → 后端仓库。

## 编号约定

**本目录用四位数字，从 `0001` 起，与上游 `Hualong Platform/docs/` 的 ADR 编号各自独立。**

上游那套（`ADR-0004`、`ADR-0005`、`ADR-0008`—`ADR-0011`）管的是平台级事项——云服务商、内容安全机制、法人主体、留存期。两套编号不共享命名空间，引用时写全路径避免歧义：本目录写 `Admin ADR-0001`，上游写 `ADR-0010`。
